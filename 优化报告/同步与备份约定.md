## 一、部署机制：符号链接 = 改完即生效

DSH 加载插件的路径是一个**符号链接（junction）**，直接指向源码目录：

```
C:\Users\<用户名>\.dsh\profiles\desktop\node_modules\dsh-qwen-paint
        └──(符号链接)──▶ C:\Users\<用户名>\Documents\dsh-qwen-paint
```

**含义：改源码目录里的文件，就等于改了 DSH 上的插件 —— 不需要复制、不需要重新安装、不需要重新打包。**

> 打包出来的 zip 只是给分享 / 备份 / 换机器用的，本机不用它。

### ⚠ 光有符号链接还不够：必须在 `bundles` 里注册才算"启用"

DSH 判断插件是"启用"还是"已停用"，看的是 **profile 的 `package.json` → `dsh.profile.bundles` 数组**：

```
C:\Users\<用户名>\.dsh\profiles\desktop\package.json
```

```jsonc
{
  "dependencies": {
    "dsh-qwen-paint": "link:C:/Users/<用户名>/Documents/dsh-qwen-paint"   // ← 装了
  },
  "dsh": {
    "profile": {
      "bundles": [
        "dsh-base", "dsh-web-app", "...",
        "dsh-qwen-paint"                                                   // ← 必须在这里才算"启用"
      ]
    }
  }
}
```

- **只出现在 `dependencies`、不在 `bundles`** → 插件管理器显示 **「已停用」**，
  界面半边（状态指示器 / 启动按钮）不会加载。
- 修复：把 `"dsh-qwen-paint"` 加进 `bundles` 数组（2026-10-09 已加），**然后重启 DSH**。
- 备份：`package.json.bak-before-enable-qwenpaint-20261009-1350`

## 二、以后每次改动的标准流程

1. **先备份**（改动前）
   ```bash
   cd C:/Users/<用户名>/Documents/dsh-qwen-paint
   cp lib/index.js "lib/index.js.bak-before-<改动名>-$(date +%Y%m%d-%H%M)"
   ```
   大改动额外做一份整体快照（见第四节）。

2. **改源码** —— 直接改 `Documents\dsh-qwen-paint\` 下的文件。
   - 配置改 `cordis.patch.yml`（这是 bundle patch 层，**升级插件不会覆盖**）
   - 逻辑改 `lib/index.js`（后端）/ `lib/client.js`（界面）

3. **跑自测**（改完立刻跑，建立基线）
   ```bash
   node scripts/_manifest_test.mjs        # package.json 完整性（防 vendor 事故复发）
   node scripts/_adapt_test.mjs
   node scripts/_intent_test.mjs
   node scripts/_opt_status_test.mjs      # 优化四态语义 + 界面侧断言（★ 15:0x 扩到 90+ 条）
   node scripts/_portability_test.mjs     # 跨平台 + 宿主 API 保护（★ 含跨平台回归锁）
   node scripts/_init_abort_test.mjs lib/index.js   # 初始化是否会被异常掐死
   node scripts/_cordis_proxy_test.mjs    # ★ 用**真 cordis** 加载插件，断言 fiber=ACTIVE
   node scripts/_draw_e2e_test.mjs        # ★ 真机出图端到端（ComfyUI 没开则自动跳过）
   ```
   > `_cordis_proxy_test` 是 2026-10-09 第四轮加的，**最重要**：
   > 它用真宿主跑真插件，能抓到所有 mock 抓不到的宿主行为（比如 Proxy 陷阱）。
   > 依赖 `_vendor/`（从 DSH 的 `app.asar` 解出的 cordis）；缺失时自动降级为静态扫描。
   >
   > `_portability_test` 的**跨平台回归锁**（第六轮加）守的是
   > "Windows 正常、Linux 必崩"那一类 bug —— 开发机是 Windows，这类问题不会自己暴露。
   > 详见 §二·六。

4. **重载 DSH** —— **插件改动必须重载才生效**（进程内模块缓存不会自动刷新）。

5. **验证** —— 三处一起看：
   - 插件管理器的状态：必须是 **运行中**，**不能是「异常」**
   - 读 `桌面\千问1生图\qwen-paint-diag.log`，看 `[host]` / `[init]` / `[route]` 几行
   - 界面上星星指示器是否变绿（在线）

## 二·五、★ cordis 宿主 API 铁律（2026-10-09 血的教训）

**`ctx` 是 Proxy。读一个"没写进 `export const inject`、当前也没就绪"的服务属性 → 直接抛错**：

```
Error: cannot get property "webServer" without inject
```

后果非常重：`apply` 抛错 → fiber 变 `FAILED` → **插件管理器显示「异常」**、
工具一个不注册、状态端点不注册 → 界面卡「正在启动中」。

### ✅ 安全属性（cordis 用 `mixin` 混入的，随便用）

| 来源 | 属性 |
|---|---|
| reflect | `get` `set` `provide` `accessor` `mixin` |
| fiber | `runtime` `effect` |
| registry | `inject` `plugin` |
| events | `on` `once` `parallel` `emit` `serial` `bail` `waterfall` |

### ✅ 正确姿势

```js
// 探测服务在不在（安全，不存在返回 undefined）
const svc = ctx.get?.('webServer')

// 必需服务 → 写进模块级 inject，然后直接 ctx.xxx
export const inject = ['tools']
ctx.tools.register(...)

// 可选服务 → 用 ctx.inject 等它出现
ctx.inject(['webServer'], (webCtx) => { … })

// 实在要读属性 → 包起来（项目里已有 safePeek 就用它）
safePeek(() => ctx?.webServer)
```

### ❌ 绝对禁止

```js
typeof ctx?.webServer            // ← 这不是"检查"，是"读属性"，会抛错！
ctx?.someOptionalService         // ← 同上
ctx?.a ?? ctx?.get?.('a')        // ← 左侧抛错就直接进 catch，右侧永远不执行
```

> **推论**：**任何"为了排查而加的诊断代码"，本身必须是最不可能出错的代码。**
> 历史上就有一次——为了"终结猜测"加的 `typeof ctx?.webServer` 快照，
> 反而把插件打成了「异常」。

## 二·六、跨平台铁律（★ 2026-10-09 新增）

> **凡是往 shell 里塞的字符串，先问一句：这在 `sh` 里是什么？**

开发机是 Windows，所以「Windows 正常、Linux 必崩」这类 bug
**永远不会自己暴露** —— 只能靠规则防。

### 唯一出口原则

所有系统命令**必须**经 `runShell`（它按平台自动选 PowerShell / `sh -c`）。
绕过它写平台专有语法 = 在另一个平台上必然崩。

```js
// ✅ 脚本按平台分叉
const script = IS_WINDOWS
  ? `& '${py}' -c "import m" 2>&1 | Out-Null; if ($LASTEXITCODE -eq 0) { 'YES' } else { 'NO' }`
  : `'${py}' -c 'import m' >/dev/null 2>&1 && echo YES || echo NO`
await runShell(script, 40000)

// ❌ 只写 PowerShell 版，没分叉 —— Linux 上 `&` 是后台运算符，语法错
await runShell(`& '${py}' -c "import m" 2>&1 | Out-Null; if ($LASTEXITCODE -eq 0) {…}`)
```

### 已修的三处（都有回归锁）

| 位置 | 问题 | 修法 |
|---|---|---|
| `probeAccelPack` | 探测脚本写死 PowerShell 语法 | 按 `IS_WINDOWS` 分叉（→ `_portability_test` A1） |
| `DIAG_FILE` | 硬拼 `home/Desktop`，绕过 `defaultOutputDir()` | 改走 `defaultOutputDir()`（→ A2） |
| `COMFY_SEARCH_WIN` | 硬编码 `C: D: E: F: G: K:` | `[char[]](65..90)` 动态枚举（→ A3） |

### 自检清单

- 新增命令前：这段脚本在 `sh` 里能跑吗？
- 涉及路径：用 `path.join` / `path.dirname`，**不要**硬拼分隔符或盘符
- 涉及"用户的桌面/主目录"：走 `defaultOutputDir()`，它已处理
  XDG → Desktop → 桌面 → 主目录，且**不会硬造不存在的目录**
- 改完跑 `_portability_test.mjs`（含跨平台回归锁）

## 三、当前默认配置（主人定的"优化档"）

写在 `cordis.patch.yml` 的 `config` 段，**任何调用生图的请求都走这一套**：

| 键 | 值 | 作用 |
|---|---|---|
| `resolution` | `1024` | 仅作**兜底**边长：调用方没传比例/尺寸时用（Qwen 原生档） |
| `steps` | `8` | Turbo8 蒸馏档（裸跑要 20–30 步） |
| `forceTurbo8Steps` | `true` | 锁死 8 步，调用方传 25 也被忽略 |
| `forceOptimizedSize` | **`false`** | ★ 2026-10-09 撤销尺寸锁：**完全听调用方**，比例原样生效 |
| `timeoutMs` | `300000` | 5 分钟上限（原 10 分钟会造成"假性卡死"观感） |
| `accelAutoInstall` | `true` | 自动补齐厂商专用加速包（失败不影响出图） |

实测这一套出图约 **7–12 秒**（模型已热时二次出图约 2 秒）。

### ★ 尺寸策略：为什么 `forceOptimizedSize` 改成了 `false`

**改前（`true`，已废弃）**：`1280x720` 这种非 1024 比例的请求，会被**静默归一成 1024x1024 方图**。
实测 **7 个比例全部塌成 1024²** —— 等于把"选比例"这个功能阉割掉了，只为了省一点算力。

| 比例 | 1.0MP 下应出 | 锁档下实际出 |
|---|---|---|
| 1:1 | 992x992 | 1024x1024 |
| 3:4 | 864x1152 | **1024x1024** ← 塌 |
| 4:3 | 1152x864 | **1024x1024** ← 塌 |
| 2:3 | 832x1216 | **1024x1024** ← 塌 |
| 3:2 | 1216x832 | **1024x1024** ← 塌 |
| 16:9 | 1344x736 | **1024x1024** ← 塌 |
| 9:16 | 736x1344 | **1024x1024** ← 塌 |

**改后（`false`）**：调用方传什么比例就出什么比例，全部 32 对齐、总像素锁在 `megapixels`。
步数锁 `forceTurbo8Steps: true` **刻意保留**——那是纯提速，不改变画面内容与构图。

> 仍想恢复尺寸锁：把 `forceOptimizedSize` 改回 `true` 即可，其余不用动。
> 图生图**从不受尺寸锁影响**（按参考图尺寸走），两种档位下都一样。

## 六、当前生效的注册模式（第三轮修复，2026-10-09 14:0x）

这是"卡在正在启动中"的**真根因**，务必按此模式写，别再回退：

```js
// ① 模块级"声明"依赖 —— DSH 会等这些服务就绪后才调用 apply
export const name   = 'qwen-paint'
export const inject = ['tools']

export function apply(root, rawConfig) {
  // ② 不再用 root.inject([...], cb) 包一层（依赖没凑齐时回调永不执行、且静默无报错）
  ;((ctx) => {
    ctx.tools.register(...)          // ③ ctx 已经带着 tools，直接用
    ctx.inject(['webServer'], cb)    // ④ 可选服务仍可用 ctx.inject（未就绪就不跑，可接受）
  })(root)
}
```

**判定改没改好的两步取证：**
1. 日志里必须有 `[inject] 准备注册 …` **紧接着** `[host] ctx API：…`；
   只有前者没有后者 = 回调被挂起（旧 bug 复发）。
2. 五组自测 + 一条 A/B：

   ```bash
   node scripts/_adapt_test.mjs && node scripts/_intent_test.mjs \
     && node scripts/_opt_status_test.mjs && node scripts/_portability_test.mjs \
     && node scripts/_init_abort_test.mjs
   ```

   `_init_abort_test` 会模拟宿主，断言「没走到状态端点注册」= 失败。

## 八、优化状态界面（★ 2026-10-09 15:0x 升级为四态）

### 为什么要有区分

优化有四项（turbo8 蒸馏 / 前缀 KV 缓存 / TE-Speed 跳步 / Speedup 残差）。
原先 `detail` 只有 `on: true/false` 二元，于是**三种完全不同的处境**
被糊成同一句"未启用"：

| 真实处境 | `state` | 用户该做什么 |
|---|---|---|
| 正常生效 | `on` | 什么都不用做 |
| 缺外部组件（如没装 TE-Speed 节点） | `available` | **装上就能快** —— 值得动手 |
| 被配置关了（如 `teSpeedEnabled=false`） | `off` | **改一行配置就能快** —— 最容易修 |
| 上游没通（如 turbo8 未生效，TE-Speed 就起不来） | `blocked` | **现在做什么都没用** —— 先解决上游 |
| 探测没成功 | `unknown` | 等 ComfyUI 起来重试 |

主人原话：「你点进去就应该是告诉你启用了哪些优化，
哪些可以启用哪些没启用，哪些不能启用」——
**这三种区分就是这一节的全部目的。**

### 数据字段（host 侧产出）

| 字段 | 说明 |
|---|---|
| `state` | `on` / `available` / `off` / `blocked`（+ 探测失败时的 `unknown`） |
| `on` | 布尔，`state === 'on'`；保留供老调用方用 |
| `action` | 一句话"该做什么"，无可做之事时为空串（UI 不渲染那行） |
| `whyOff` | 原有字段，保留 |
| `stats` | 四态计数 `{on, available, off, blocked, total}` |

### 两个入口（单一数据源）

| 入口 | 行为 |
|---|---|
| 状态行右侧**徽标** | 任何状态都可点（★ `full` 以前不可点，那是 bug） |
| 设置菜单的**「优化」组** | 显示 `3/4 已启用 · 1 可启用`，点它弹**同一个**面板 |

> ⚠ **菜单不许自己造面板**，必须复用徽标的 `openDetail()`。
> 两套渲染必然逐渐走样，用户看到"徽标点开"和"菜单点开"不一样 ——
> 那是最糟的一类 bug。改动这块时**守住这条**（有断言）。

### 无障碍

四态**不止用颜色**，各有独立字形（`✓` / `✕` / `?`）—— 色觉障碍用户也要能分辨。
