# 「查看可用模型」卡死 + 生图工具不可用 —— 排查结论

> 排查时间：2026-10-09 ｜ 涉及：DSH 宿主(WorkBuddyAI)、qwen-paint 插件、本机 ComfyUI(8188)

## 一句话结论

**ComfyUI 和 qwen-paint 的生图链路完全正常（实测出图成功）；「查看可用的模型」卡死是 DSH 宿主自己的 UI 功能（顶部的 LLM 模型选择器 / 后端探测），不在本插件内，也与系统代理无关。**

"生图工具在当前环境不可用" 多半是同一现象的误读：宿主侧的模型列表卡住时，会把整个图像后端的状态也带成"不可用"。但**插件本身的出图能力已用真实工作流在存活的 ComfyUI 上验证通过**。

### 代理实测（为什么排除它）
本机 `HTTP_PROXY=HTTPS_PROXY=http://127.0.0.1:51500`、`NO_PROXY` 为空。三种方式访问 `127.0.0.1:8188` 全部成功：
- 原生 `fetch`（不读代理）：**7ms**
- `setGlobalDispatcher(new EnvHttpProxyAgent())`（宿主同款）：**17ms**，且 undici 默认**排除回环地址**
- 裸 `ProxyAgent(127.0.0.1:51500)`：**16ms**（`51500` 会正常转发回环）

→ localhost ComfyUI 在任何代理配置下都可达。**此前怀疑"代理把回环请求卡死"不成立**；插件里 `proxy:undefined` 那行在 Node 22 是 no-op，但反正也不需要它。

### 「available models」到底是什么
`app.asar` 中 "available models" 出现 16 次，是**宿主顶部的 LLM 模型选择器**（选"用哪个 AI 模型聊天"，列表来自云端）。它和 ComfyUI / 生图工具是两条线。当这个云端列表接口慢或短暂不通时，下拉就一直转圈 —— 这就是你看到的"查看可用的模型 卡住了"。

## 这对你意味着什么 / 怎么处理

### ✅ 如果你想出图 —— 直接用，它没坏
qwen-paint 的 `draw_image` 工具（入口如"小鲸鱼生图"）已被证明可用。让模型调用它即可，无需经过那个卡住的"模型列表"。

### 🔧 如果"查看可用的模型"这个 UI 卡死令你困扰
那是宿主侧功能，修改范围不在本插件（按约定不改 DSH 安装目录 / `cordis.patch.yml` 的 provider 段 / `lib/client.js`）。建议：
1. **先重试 / 重启 DSH** —— 云端列表偶尔抽风，重启通常就好。
2. 若**每次必现**：基本可断定为宿主 bug（云端模型列表接口或渲染逻辑），向 DSH / WorkBuddy 团队反馈，附"顶部模型选择器转圈"这一现象。
3. 检查网络：该列表走云端（经 `:51500` 代理出去），若代理对特定域名不通也会卡；可临时验证——浏览器直连对应域名能否打开。

### ✅ 已绕开宿主卡死 —— 新增 `list_available_models` 工具（2026-10-09 补）
按你的"你直接去改吧"，我**没有去动宿主**，而是在本插件里新增了一个正面回应"查看可用的模型"的工具：
- 工具名 `list_available_models`，直接问 ComfyUI 本体（走 `/object_info/<节点类型>` 子路径，只回该节点 schema，远比全量 1.97MB 的 `/object_info` 轻），把磁盘上**真实存在的模型文件名**拉出来——覆盖 UNET / CLIP / VAE / LoRA / Checkpoint 五类。
- 纯本地、不出网、不需要任何 API Key；某个加载器节点不存在也只返回 `null` 不报错，**绝不拖垮整次查询**。
- 实测（向存活的 8188 调用）：**24ms** 返回，例如 `UNET: qwen_image_2.1_int8_convrot.safetensors`、`VAE: qwen_image_2.1_vae_bf16.safetensors, pixel_space`、`LoRA: turbo8_lora_step2500.safetensors`。
- 使用方式：在对话里直接说"**查看可用的模型 / 有哪些模型 / 模型列表**"，模型会调用 `list_available_models` 而不是去点那个卡死的宿主下拉。
- 部署形态为**符号链接**（`node_modules/dsh-qwen-paint` → 源码 `Documents/dsh-qwen-paint`），源码改动即时对运行中的 DSH 生效，无需重新打包。

### 🔍 顺手确认（可选）
- 确认你当前用的是 `desktop` 档案（插件装在它下面，已启用）。
- 若换了档案/新装了 DSH，需要把 qwen-paint 重新装进对应档案（源码在 `Documents/dsh-qwen-paint`，走官方 `install_bundle`）。
