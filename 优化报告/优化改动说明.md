# 千问-0.1.2 已优化版 —— 改动说明

本包基于 `(绘图)千问-0.1.2.zip`（基础版）改造为**已优化 · 通用版**。

> 目标：任何人下载本包，装到自己机器上，**不需要手工改配置**就能：
> ① 自动认出 ComfyUI 装在哪；② 自动识别显卡厂商与代系并套用对应优化；
> ③ 自动探测 ComfyUI 有哪些节点/模型，据此选一档可用的最快链路。

---

## 一、第一轮：生图链路优化（turbo8 八步蒸馏）

基础版 0.1.2 **尚未含 Turbo8 优化栈**。本包把已验证的优化链路整体带入：

1. **Turbo8 八步蒸馏链**：`LoraLoaderModelOnly`(turbo8) + `ModelSamplingFlux` +
   `QwenImage21Cache`(int8 前缀 KV 缓存)
2. **两层跳步缓存**：`TESpeedQwenImage21` + `QwenImage21Speedup`
3. **步数/尺寸双锁**：`forceTurbo8Steps` + `forceOptimizedSize`
4. **`list_available_models` 工具**：直接问 ComfyUI 拉真实模型清单
5. **超时 600000 → 300000**

**本机实测**（RX 7900 XT / ComfyUI 0.39.0 / 1024²，每遍换 seed 的稳态值）：
91.6s（原 30 步基线）→ 12.6s（turbo8）→ 9.7s（+TE）→ 8.2s（+Speedup+quad）。

## 二、第二轮：修复"调用仍然未优化"的根因

先说结论：**插件源码本身没有问题**。用插件自己的 `buildWorkflow` 实测导出，
即使调用方传 `1328×1328 / 25 步`，也会被强制锁成 `1024×1024 / 8 步 / CFG 1 / 全栈`。
问题出在**配置与打包环节**，共修 4 处：

| # | 问题 | 后果 |
|---|---|---|
| ① | `cordis.patch.yml` 里 ComfyUI 路径指向一个**不存在的目录** | 插件后台自启 ComfyUI 必然失败 |
| ② | `comfyArgs` 显式给了参数，**整个绕过**了按显卡自动选后端的逻辑 | 自启实例跑在无效的注意力后端上 |
| ③ | 打包白名单不含工作流 JSON 与报告 md | 它们从没进过包 |
| ④ | 报告与调试脚本里写死了开发机绝对路径 | 触发打包隐私检查，**必然中止** |

另外修掉一个打包 bug：`SKIP` 规则只认 `_backup` 目录、不认 `.bak-` 后缀，
导致 7 个开发备份混进首版产物。

## 三、第三轮（本次）：通用化 + 三厂商自适应

### 3.1 路径不再写死 —— 自动探测 ComfyUI

**任何人装的盘符、目录名都不一样**（官方便携包 / 源码 + venv / 改名安装）。
现在按三级回落找它：

1. 配置里显式给了 → 直接用
2. 从**正在运行的** ComfyUI 进程反查（最准，它自己带着完整命令行）
3. 扫常见位置 + **各盘根目录下名字含 `comfy` 的目录**（能覆盖 `ComfyUI-rocm` 这类改名安装）

都找不到才报错，并给出可直接照抄的配置模板。实测在本机能自动找到
`X:\ComfyUI`，无需任何配置。

### 3.2 GPU 厂商 / 代系自适应

**两层优化要分清楚**：

- **通用优化**（与显卡无关，所有卡都吃）：turbo8 八步链、前缀 KV 缓存、跳步缓存
- **专用优化**（与厂商强绑定）：注意力后端启动参数 + 厂商专属内核

厂商判定采用**打分制**（明确型号 > 泛化厂商名 > 核显）。这一点是必须的：
一台机器可能同时报出核显 + 独显（如 `AMD Radeon Graphics | NVIDIA RTX 4090`），
按数组顺序匹配会先命中 AMD 核显而**判错**。实测这两组混装场景都能正确选中独显。

| 识别结果 | 判定依据 | 采用的注意力后端 |
|---|---|---|
| **AMD RDNA3**（RX 7000 系 / gfx11xx） | `Radeon RX 7xxx` / `gfx11xx` | `--use-quad-cross-attention` — **既有方案，保持不变**（实测 +15%） |
| **AMD RDNA4**（RX 9000 系 / gfx120x） | `Radeon RX 9xxx` / `gfx120x` | `--use-pytorch-cross-attention` — **换用 CK SDPA 专用内核** |
| **AMD RDNA2**（RX 6000 系 / gfx103x） | `Radeon RX 6xxx` / `gfx103x` | `--use-pytorch-cross-attention` — 保守路径（见下） |
| **NVIDIA**（CUDA，通用） | `GeForce` / `RTX` / `Quadro` 等 | `--use-pytorch-cross-attention`（PyTorch 原生 SDPA 已走 flash 内核） |
| **Intel Arc B 系**（B580 / B570，Battlemage / Xe2） | `Arc.*B\d{3}` | `--use-pytorch-cross-attention`（XPU + IPEX） |
| **Intel Arc A 系**（A770 / A750 / A580，Alchemist） | `Arc.*A\d{3}` | `--use-pytorch-cross-attention`（XPU + IPEX） |
| 认不出 | — | **不加任何参数**（宁可少点性能，也要保证能起来） |

> **RDNA2 为什么单独一档**：ROCm 的融合注意力路径 AOTriton **只覆盖 RDNA3 / 3.5 / 4**，
> RDNA2 不在其列，CK SDPA 同样不覆盖它。这代卡上**没有可用的厂商级融合内核**，
> 所以不套用 quad，把内核选择权交回 PyTorch，先保证能跑、不崩。
>
> **RDNA4 为什么要换内核**：RDNA4 走的是 PyTorch 的 **CK SDPA** 路径，而它在
> gfx1200/gfx1201 上**长期是坏的**（内核断言失败，pytorch#188113），
> 后来的 PR #188414 / #193585 才修好并放开 —— 所以 9000 系**需要较新的 PyTorch**。

### 3.3 A 卡策略：不引入额外内核

按你的要求，**A 卡用户沿用既定方案**（通用链 + 对应后端参数），
**不额外下载任何第三方内核**。唯一例外是 RDNA4 在启动参数上换用 CK SDPA，
而那是 PyTorch 自带的，同样不需要下载东西。

### 3.4 缺件不再"整单硬失败" —— 能力探测 + 自适应降级

这是通用化最关键的一点。优化链上每一环都是**可选依赖**，别人机器上未必有：

- `turbo8_lora_step2500.safetensors`（1.36 GB，要自己下）
- `TE-Speed-QwenImage21` 节点（闭源 `.pyd`）
- `ComfyUI-Qwen-Image-2.1-Speedup` 节点
- `QwenImage21Cache` 节点（要足够新的 ComfyUI）

而 ComfyUI 遇到"引用了不存在的节点类型"或"模型名不在候选列表里"是**整单拒收**
（`node type not found` / `value not in list`），**不会静默降级**。
老版本一旦发出去，没装全的人一画图就报错 —— 包等于是坏的。

现在：出图前先**问 ComfyUI 本人**（`/object_info/<节点类型>`），摸清"有哪些节点、
磁盘上模型文件真实叫什么"，据此选一档可用的最快链路（结果按地址缓存 10 分钟）。

| 档位 | 条件 | 实际链路 |
|---|---|---|
| `full` | turbo8 LoRA + 跳步缓存齐 | 全栈：8 步 / CFG 1.0 / 9 节点链 |
| `turbo` | 有 turbo8 LoRA，缺跳步缓存 | 8 步 / CFG 1.0，跳过缺的那一环 |
| `basic` | **没有** turbo8 LoRA | 回退 **25 步 / CFG 2.5**（慢，但任何千问环境都能出图） |
| `unsupported` | 连千问模型都匹配不到 | 沿用配置里的文件名，让 ComfyUI 报原始错误 |

**一个必须点出的细节**：`basic` 档**绝不能**继续按 8 步 / CFG 1 跑 ——
那是 turbo8 蒸馏 LoRA 的工作点，缺了 LoRA 跑 8 步只会得到一张糊图。
所以步数与 CFG 是**跟着链路一起降级**的。

同理，TE-Speed / Speedup **刻意只在 turbo 链路启用**：它们的阈值（0.06 / te_predictor）
是针对 8 步链路调出来的，挪到 25 步上意味着完全不同的跳过行为，未经验证会动画质。

### 3.5 模型文件名模糊匹配

作者用的是 int8 量化版（`..._int8_convrot` / `..._w4a8`），别人下的可能是 bf16 或 fp8 版，
文件名并不相同 —— **写死文件名 = 换台机器就拒收**。现在按关键字优先级从
"磁盘上真实存在的"列表里挑最合适的（int8 > fp8 > 其他）。

### 3.6 厂商专用加速包：探测 + 可选安装

新增工具 **`check_acceleration`**：

- `action=status`（默认）：**纯只读** —— 报告识别到的显卡、采用的参数、
  通用优化就位情况、厂商专用包装没装、还差什么。不联网、不下载。
- `action=install` + `packId`：安装白名单内的加速包。

白名单（只放**来源明确、可查证**的包，绝不接受任意 URL / 任意包名）：

| id | 适用 | 定位 | 来源 |
|---|---|---|---|
| `triton-windows` | NVIDIA | **前置组件**：Windows 上 Triton 的构建，SageAttention 等一批内核都依赖它 | [woct0rdho/triton-windows](https://github.com/woct0rdho/triton-windows) |
| `sageattention` | NVIDIA | **主力**：INT8 量化注意力，扩散模型圈近两年最主流的 N 卡注意力加速 | [thu-ml/SageAttention](https://github.com/thu-ml/SageAttention) |
| `nunchaku` | NVIDIA | **进阶**：SVDQuant 4-bit 量化推理。⚠ 需先把模型转成其专用格式，不作为默认推荐 | [nunchaku-tech/nunchaku](https://github.com/nunchaku-tech/nunchaku) |
| `ipex` | Intel Arc | PyTorch XPU 扩展与算子优化（B580 / A770 都走它） | [intel/intel-extension-for-pytorch](https://github.com/intel/intel-extension-for-pytorch) |

**AMD 一支刻意留空**：按你的要求，A 卡沿用既定方案（通用链 + 对应后端参数），
**不引入任何第三方内核**。唯一例外是 RDNA4 在启动参数上换用 CK SDPA，而那是 PyTorch 自带的。

> **保守原则**：以上都是"**能装、但不默认装**"。所有条目 `verified: false` ——
> 表示方案真实存在且社区评价良好，但**未在对应硬件上实测过**。
> 安装还需真实环境，见下面的默认值说明。

> **为什么默认不允许自动安装**（`accelAutoInstall: false`）：
> 安装加速包 = 在用户机器上 `git clone` 并执行第三方代码，属于对用户环境的**实质性改动**，
> 还依赖网络、git、pip 与对应 torch 版本。一个绘图插件在后台静默做这件事，
> 风险和观感都不合适 —— 所以发行默认关掉，由使用者显式打开。
> **你要全自动**：把 `cordis.patch.yml` 里的 `accelAutoInstall` 改成 `true` 即可。

### 3.7 其他通用性修正

- `comfyOutputDir` 默认**留空** → 取图直接走 `/view`（不再先白读一次不存在的目录）
- `comfyAttentionBackend` 默认 `'auto'`（原来写死 `'quad'`，那只对 A 卡成立）
- PowerShell 输出编码钉成 UTF-8（否则 WMI 返回的中文显卡名会乱码）

## 四、第四轮：代码审查 —— 找出来的隐形 bug

这一轮没加功能，专门盯**"表面正常、实际会出错"**的地方。查出并修掉 8 处，
其中第 1 条是会直接毁掉画质的真 bug：

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| 1 | **`steps` 回落到 `cfg.steps`（= 8）** | basic 档（没装 turbo8 LoRA）也会拿到 8 步 → **直接出糊图**，把"没 turbo8 就回退 25 步"的设计整个抵消 | 不传就如实传 `undefined`，由链路决定默认值；`execute` 与 `planWorkflow` 两处同步改 |
| 2 | `getNodeSchema` 用 `null` 同时表示"节点没装"和"查询失败" | **一次网络抖动就被当成"缺件"**，静默降级、还缓存 10 分钟 —— 用户莫名变慢且毫无提示 | 改成三态 `ok` / `missing` / `error`，只有 `ok` 才算"有" |
| 3 | 探测失败也照样写缓存 | 一个错误结论被钉住 10 分钟 | 只有"探测可信"且**未被取消**时才缓存 |
| 4 | 探测失败时按"缺件"处理 | 同上，静默降级 | 改按"能力齐全"去试：**明确报错优于静默变慢** |
| 5 | 启动 ComfyUI 前仍去敲 `/system_stats` | 每次都白等一次 6 秒超时（走到这条路径时它**必然**没在跑） | 加 `skipOnline` 跳过；GPU 判定另加 1 小时缓存 |
| 6 | 扫盘时遍历**所有**驱动器 | 有网络盘/映射盘时 `Get-ChildItem` 可能卡到超时 | 只扫本地盘（`X:\` 形式） |
| 7 | 安装后不验证；`custom_node` 只看目录是否存在 | `git clone` 中断留下的**空壳目录**会被当成"已装好"，以后再不重试；pip 失败也报成功 | 装完**重新探测**判定；目录要求非空 |
| 8 | 没装 git 时直接 `git clone` | 用户只看到"git 不是内部或外部命令"，不知道怎么办 | 先预检 git，给出可照做的提示（含手动下载替代方案） |

另外修掉一处文档不一致：`buildWorkflow` 注释里引用了 `optimizedSize`，
但该配置项**并不存在**（实际走 `resolution`）。

**回归防护**：以上第 1、3、4 条都补了**专项断言**进 `scripts/_adapt_test.mjs`
（标着 `★回归`），以后改代码若把它们碰坏，自测会立刻失败。

## 五、第五轮：Linux 适配 + 多源下载 + 兜底

### 5.1 Windows / Linux **两套平行方案**

之前所有系统命令都是 PowerShell 专有的，Linux 上直接崩。现在：

- 新增唯一入口 `runShell()`：Windows → PowerShell（并把输出编码钉成 UTF-8），
  **Linux / macOS → `sh -c`**（POSIX，**不假设有 bash** —— 精简发行版里可能只有 dash）。
- **GPU 识别**两套并列：
  | 平台 | 取显卡信息的方式 |
  |---|---|
  | Windows | WMI `Win32_VideoController` |
  | Linux | `nvidia-smi` → `rocm-smi` → `lspci` → `/sys/class/drm/*/device/vendor`（四级回落，工具没装是常态） |
  最终都归一成一行文本，喂给**同一套**厂商识别规则（打分制），所以 A/N/I 卡与各代系判定逻辑完全共用。
- **ComfyUI 路径探测**两套并列：Linux 侧找 `venv/bin/python` + `ComfyUI/main.py`，
  并扫 `/opt`、`/mnt`、`/media`、`/srv` 与家目录下名字含 comfy 的目录。
- **加速包按系统过滤**（`packAppliesToOs`）：`triton-windows` 只在 Windows 装，
  `triton`（官方构建）只在 Linux 装 —— **装错了会顶掉正确的那个**。

### 5.2 多套下载方案，一套不通自动顶上

用户网络千差万别（挡 GitHub、pip 官方源不通、只有国内镜像可达、代理只放行部分域名），
**单一下载源必然有人装不上**。所以每个包都给 **5 套**候选，按序尝试、任一套成功即止：

```
PyPI 官方源 → 清华 TUNA 镜像 → 阿里云镜像 → 腾讯云镜像 → GitHub 源码直装
```

（IPEX 特殊：它**不在 PyPI 上**，必须带 Intel 扩展索引，标签里已注明。）

另外 pip 统一带 `--timeout 15 --retries 1`：让"连不上"**快速失败**并切下一套，
而不是卡在 pip 默认的长重试里（观感就是"卡死"）。返回值会记录**实际用了哪套源**。

### 5.3 内置通用配置 —— 下载全失败也照样出图

这是"不依赖任何下载"的兜底，已实测：把能力探测结果设成**最差情况**
（无任何自定义节点、无 LoRA），插件产出的工作流退化为：

```
UNETLoader → CLIPLoader → VAELoader → TextEncodeQwenImage21
           → EmptyLatentImage → KSampler(25 步 / CFG 2.5) → VAEDecode → SaveImage
```

**只用到 ComfyUI 原生节点 + 千问模型本身**，一个下载件都不需要。
换句话说：加速件全是"锦上添花"，缺了只会慢，**绝不会不可用**。

### 5.4 自动检测 + 自动下载

`accelAutoInstall` 默认 **true**：插件加载后 20 秒**自动检测**缺哪个厂商专用加速包，
缺就**自动下载安装**（延迟 + unref，不拖慢加载与出图；全程失败只写日志）。

包内**只带这套"下载器"逻辑，不预置任何已下载的文件** —— 所以包的体积只有 ~500 KB
（大头还是那 358 KB 的 UI 动画）。介意自动改动环境的话把它设为 `false` 即可。

### 5.5 ⚠ 未验证的部分（如实说明）

- **Linux 分支未实测**。本机是 Windows，WSL 也没装发行版，所以 Linux 的
  GPU 探测、路径扫描、下载命令**只做了静态审查，没有真跑过**。
  好消息是所有 Linux 调用点都有 catch 兜底 —— 失败会优雅降级（返回 unknown / null），
  **不会崩**，只是退回到"配置里手动指定路径"。
- 各家专用加速包（SageAttention / Nunchaku / IPEX / Triton）的**实际收益与安装成功率为推导**，
  未在对应硬件上验证 —— 白名单里都标了 `verified: false`。

## 六、第六轮：代码审查（隐患 / 精简 / 语法现代化）

这一轮不动功能，专治**质量**问题。查出 1 个真 bug、3 处跨平台缺口、若干冗余。

### 6.1 真 bug：跨平台引号转义不一致 ★

`runInstallSource` 里给 pip 拼命令行时用了 **sh 风格**转义（`'\''`），
却在 Windows 分支把它交给 **PowerShell**（PowerShell 按 `''` 转义单引号）。
结果：Windows 上安装参数一旦含单引号就会被解析错。
已改为**按平台选转义函数**（`q()`），并顺手把 `env.py` 的转义也统一到它上面。

### 6.2 跨平台缺口：3 处命令**只有 Windows 版** ★

上一轮我做了平台抽象，但漏掉三处 —— 它们在 Linux 上会直接失败：

| 位置 | 原命令（PowerShell 专有） | Linux 后果 |
|---|---|---|
| 启动 ComfyUI | `Start-Process -WindowStyle Hidden` | **完全拉不起 ComfyUI** |
| 查找 ComfyUI 进程 | `Get-NetTCPConnection` + `Get-CimInstance` | 无空闲关停（不误杀，但也关不掉） |
| 停止 ComfyUI | `Stop-Process -Force` | 同上 |

修法：
- **启动**改用 Node 原生 `spawn`（跨平台一致，还免去手工拼接/转义命令行那串三层嵌套的引号替换），
  `detached + unref()` 保证插件重启不带走 ComfyUI，`stdio:'ignore'` 给它一个可用但被丢弃的输出流
  （**不能用 `inherit`** —— 宿主没有终端；也不能用 pythonw，那个 stdout 是 `None`，一 print 就崩，这个坑踩过）。
  另外 `spawn` 的失败是**异步事件**，必须挂 `error` 监听，否则会变成 uncaught exception 把插件搞崩。
- **查找/停止**补齐 Linux 分支：`lsof -ti tcp:<port> -sTCP:LISTEN`（退回 `ss` + `sed` 提 `pid=`）、
  `ps -p <pid> -o args=`、`kill`（先 SIGTERM 再兜底 SIGKILL）。
- `--windows-standalone-build` 只在 Windows 加（Linux 上无意义）。

### 6.3 结构整理：平台层挪到使用者之前

`IS_WINDOWS` / `runShell` / `GPU_PROBE_*` / `COMFY_SEARCH_*` 原先定义在 **1300 多行**，
而首次使用在 **539 行**。（因为函数声明会提升、模块顶层又不调用，所以能跑，但读起来别扭。）
已整块前移到路径探测之前 —— **先有平台层，再有使用者**。

### 6.4 精简

| 项 | 处理 |
|---|---|
| `resolvePlan` 里三处 `c === FULL_CAPS \|\|` | **删除** —— 完全冗余：`FULL_CAPS.level` 就是 `'full'`、`nodes` 也全 `true`，条件本就成立 |
| `runInstallSource(source, env, log)` 的 `log` | **删除** —— 函数体从未使用（错误由调用方处理） |
| `ACCEL_PACKS.ipex.extraIndexUrl` | **删除** —— 索引地址已统一由 `ACCEL_SOURCES` 提供，该字段无任何引用 |
| `custom_node` / `gitClone` 分支 | **标注为扩展预留** —— 当前白名单全是 pip 包，这些分支走不到，但不删（将来收录只能 git clone 的节点时不用改） |

### 6.5 性能：探测改并发

- `probeAcceleration` 原先**串行**跑三项探测；其中每个加速包都要**起一次 Python**（`import` 检查），
  N 卡上 3 个包 = 白等好几秒。现已全部 **`Promise.all` 并发**。
- `generic` 字段（通用优化清单）原先是一张**静态数组**，不管实际启没启用都那么写；
  现在跟着**同一次能力探测**走，会明确标出每项**已启用 / 未启用**，以及当前跑在哪个采样档位上。

### 6.6 语法现代化

- `if (log) log(...)` → **`log?.(...)`**（可选调用，5 处；语义等价但少一层判断）
- `const probe = {}` + `forEach` 赋值 → **`Object.fromEntries(...)`**（一行表达"按 key 映射"）

### 6.7 跨平台细节：出图目录

`outputDir` 原先无脑拼 `~/Desktop`。**Linux（尤其无桌面环境的机器、服务器、WSL）常常根本没有
`~/Desktop`**，硬拼会造出一个用户压根不用的目录。现在按
`XDG_DESKTOP_DIR → ~/Desktop → ~/桌面 → 主目录` 顺序**真的去检查存在性**，都不存在就直接落主目录。

## 七、第七轮：DSH 联动性改造（意图判定 + 启用开关）

### 7.1 问题：原来靠一段"越长越好"的提示词赌模型能猜对

原先的做法是让模型自己从一段堆了十七次的长提示词里领悟用户想不想画图。
两个硬伤：

1. **没教它排除**。"画个流程图 / 思维导图 / 表格 / 架构图"这类请求**看着像生图**，
   但用户要的是文字或图表，不该用本工具 —— 老提示词对这种边界一个字都没提，
   模型很可能直接画出一张莫名其妙的图。
2. **一刀切，用户没有选择权**。有人就想要个安静的工具（只在明确点名时才画），
   有人就想让它积极点（沾边就画），但老版本只有一套话术，改不了。

### 7.2 新增 `drawTrigger`：四档意图判定策略

| 档位 | 行为 | 适合 |
|---|---|---|
| `off` | 不做主动引导，只在用户**直接点名**要画图时才画 | 想要个安静工具的人 |
| `strict` | 只在**明确要求**且**描述具体**时才画；模糊的**先问一句** | 怕误触发的人 |
| `auto`（默认） | 判断是生图请求就画；但**排除**流程图/表格这类场景，那种**先确认** | 大多数人 |
| `eager` | 只要沾边就画（最积极） | 确定只用它画图的人 |

**四档都补上了边界规则**：明确告诉模型"画个流程图/思维导图/表格"不属于本工具，
**判断不准时宁可先问一句，也不要画错**。同时把这条边界也写进了 `draw_image` 的
**工具描述**里 —— 工具描述比 systemPrompt 更靠近"要不要调这个工具"那一刻。

**无论哪一档，都不会在用户没有生图意图时去调工具**（最松的 `eager` 也只是"沾边就画"）。

顺带**消掉了三份重复的长文本**：原来同一段话术在文件里抄了三处，改一次要改三地；
现在抽成 `buildDrawIntentPrompt()`，四档的**共通纪律**（一次只生一张、不写耗时尺寸、
思考极简）只写一遍。

### 7.3 新增 `enabled`：插件总开关

`false` → 插件对 DSH 相当于**"不存在"**：不注册 `draw_image`、不注入任何提示词、
不预热 ComfyUI、不做空闲关停。

但**保留** `check_acceleration` / `list_available_models` 两个**诊断类**工具
（它们只读、不画图）—— 否则关掉之后真出了问题，连查都没法查。

用途：临时收起画图能力而不卸载 / 同一个 DSH 跑多个图像后端时避免抢话 / 排查问题时把插件摘出去。

### 7.4 回归防护

新增 `scripts/_intent_test.mjs`（**25 项断言**，已随包发布），钉住：
- 四档生成的提示词**确实语义不同**（不是换个名字而已），且互不相同
- 未知值 / `undefined` 都安全回落到 `auto`（不抛错）
- 四档**共通纪律一个都不能少**（每档各查三条）
- 默认值正确（`enabled=true` 装上即用、`drawTrigger='auto'`）

## 八、第八轮：界面显示"优化是否已启用"（含未启用原因）

### 8.1 问题：优化状态只躺在日志里

用户装完插件，界面上只有一个 ComfyUI 在线圆点，**完全不知道** turbo8 到底跑没跑。
如果没跑，是因为没装 LoRA、ComfyUI 太旧、还是探测压根没成功？——全无线索。
体感就是"怎么这么慢"，然后无从下手。

### 8.2 做法：状态点旁边加一个优化徽标

在 ComfyUI 状态点**右边**加一个小徽标，六个状态：

| 徽标 | 含义 | 可点击 |
|---|---|---|
| `优化已启用` | 四项全生效（8 步 / CFG 1.0 全栈） | — |
| `优化部分启用` | 有 turbo8 但缺某一环 | ✓ 看缺了什么 |
| `未启用优化` | 没 turbo8，回退 25 步原生链路 | ✓ 看怎么办 |
| `优化未确认` | 探测失败（**不是缺件**） | ✓ |
| `插件已停用` | `enabled=false` | ✓ 看怎么恢复 |
| `优化检测中` / `优化未检测` | 启动中 / ComfyUI 没运行 | — |

点开面板会给出**逐项明细**（✓/✕）和**可直接照做的原因**，例如：
> · 未启用：没在 ComfyUI 的 loras 目录里找到 turbo8 LoRA（当前回落的文件名是
>   「turbo8_lora_step2500.safetensors」，看起来并不存在）。把 … 放进 models\loras 即可。
> · 未启用：ComfyUI 里没有 QwenImage21Cache 节点 —— 通常是 ComfyUI 版本偏旧，升级即可。

### 8.3 三条设计底线

1. **必须给出"为什么"**，不能只显示"未启用"—— 每条 reason 都要能直接照做。
2. **严格区分"确实缺件"与"没测出来"**。探测失败时明确提示"这不代表缺件、也不代表优化没生效"，
   否则用户会跑去装一堆根本不需要的东西。
3. **绝不允许把 UI 搞崩**。`describeOptimization` 对任何脏输入都返回可显示对象（5 种脏输入已测）。

### 8.4 尺寸克制

徽标只放 4~6 个字 —— 主人此前**两次**反馈状态行文字过长会把"推理流光条"挤到第二排。
详细原因一律走点击弹出的面板，不占状态行宽度。

### 8.5 顺带修掉的两个真 bug

| 问题 | 影响 |
|---|---|
| `describeOptimization` 的"是否全启用"只算了 turbo8 + 前缀缓存，**漏算 TE/Speedup** | 缺 TE-Speed 时会**误报"优化已启用"** —— 报告等于骗人。已改为四项全算，并让 summary 点出缺了哪项 |
| `lib/index.js` 里一行 **嵌套模板字符串**（反引号里又套反引号） | `node --check` 直接报语法错，**整个文件都过不了**。已拆成先算变量再插值 |

### 8.6 回归防护

新增 `scripts/_opt_status_test.mjs`（**33 项断言**，随包发布），钉住六种状态各自的
level / summary / reasons，以及 5 种脏输入不抛错。

## 九、第九轮：面板裁切修复 + 性能隐患排查 + UI 通用性

### 9.1 修：「优化详情面板只显示一半」★

根因和菜单当初一模一样：面板用的是 `position: absolute`，而它在 **composer 的祖先链**里，
那一串祖先带 `overflow` 裁剪 —— **裁在祖先层，翻方向/限高/滚动统统救不了**
（裁的是元素可见区域，不是它自己的滚动内容）。

修法：面板也改成 **`position: fixed` + 挂到 `body`**，位置每次打开现算（`placePanel`）：
优先向上弹，塞不下就翻到下面，水平贴徽标但不越界。与祖先裁剪彻底无关。

顺带：记住并还原面板滚动位置（内容长时每次点开都跳回顶部很烦人）。

### 9.2 修：重复请求 / 浪费算力 ★

状态端点是**每 5 秒轮询一次**的，而它每次都会走一遍能力探测（**一轮 10 个 HTTP 请求**：
9 个 `object_info` + 1 个 `system_stats`）。查出两处隐患：

| 隐患 | 后果 | 修法 |
|---|---|---|
| `probeCapabilities` **探测失败时完全不缓存** | ComfyUI 在线但不稳定时，**每 5 秒重发那 10 个请求** | 失败也缓存，用**短 TTL（30 秒）**；缓存条目自带 ttl |
| `queueBusy()` **没有任何缓存** | 每轮轮询固定多打一次 `/queue`（而 `probe()` 是有缓存的，两边不对称） | 加 2 秒短缓存 |

客户端也补了两处"无谓重绘"：
- `paint()` 每 5 秒重设 `data-state`/`textContent` → 值没变就**不碰 DOM**
- 优化徽标同理（`lastCls`/`lastText` 比对）

新增 `scripts/_perf_test.mjs`（随包发布）做**实证**验证：实测第二次探测 **0 ms** 命中缓存，
并确认 `statusCacheMs` 等配置合理。

### 9.3 UI 通用性（笔记本 / 台式 / Win / Linux / 任意系统字号）

**上次改坏输入框的教训：这一轮一个内核覆盖样式都没动** —— 只改插件自己的类
（`.dshqp-*` / `.qwen-paint-*`）。事后逐项核对过：`data-composer-card`(10)、
`data-lexical-editor`(3)、`class*="_scroll"`(2)、`class*="_root"`(1) 数量与改版前**完全一致**。

| 项 | 改动 | 解决什么 |
|---|---|---|
| 面板尺寸 | `width: min(360px, calc(100vw - 24px))`；`max-height: min(62vh, 460px)` | 小屏 / 分屏时不撑出视口 |
| 面板文字 | `word-break` + `overflow-wrap: anywhere` | 长路径 / 长英文不撑破容器 |
| 面板字号 | 11.5px → **12px** | Linux 字体渲染偏大时不至于糊成一团 |
| 菜单 | 加 `max-width: calc(100vw - 16px)` | 窄屏时不再被顶出去截断 |
| 菜单项 | 加 `max-width: 100%; overflow: hidden` | 系统字号调大时条目裁剪而非撑破 |
| 出图卡片 | `max-width: 380px` → `min(380px, 100%)` | 窄容器里不溢出 |
| 状态座位 | 加 `min-width: 0` | 允许收缩，长文案不顶破工具行 |

### 9.4 颜色选择优化

原来色块只有 **10×10、圆角 3px**。问题是这些流光都是**多色标渐变**（多数 7~11 个色标），
缩到 10px 后相邻色标糊成一片，**根本看不出这档到底是什么颜色 —— 选色等于靠猜**。

现在：**16×14、圆角 4px**（略扁，更贴近 9:16 动画的实际观感）、边框加深一档、
加一道内描边提升质感。
