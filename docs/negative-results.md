## 外部教训引用（hipfire 优化战役，2026-10，来自桌面优化改动报告）

与本插件同源的启发式教训（完整 14 项见该报告第六节）：

- **"看起来更简洁"的三连否定**：contextlib.suppress 慢 33 倍、dict 分派慢 7 倍、f-string 在该场景慢 1.3%——简洁性与性能冲突时，热路径以性能为准（对应本仓库：lib/ 体积红线下的写法也以护栏实测为准）。
- **并行化的隐藏代价**：把工具执行移出锁外"提升并发"，实测摧毁了缓存防踩踏（16 线程同 key 执行 16 次），已回滚。→ 对应本仓库 TTS 分块串行是刻意设计。
- **A/B 三臂×多样本才算数**：单点数字可能是噪声（hipfire 的 HW 队列三臂全在噪声内）。→ 本仓库所有倍率数字必须真机实测、注明机器档位，同一纪律。
- **单点优化先算占比**：hipfire 的 −49% Python 优化只占请求总耗时 0.018%。→ 本仓库修性能前先估"在用户可感知路径上的占比"，job-queue stats 这类低频调用不值得重写。
